# Executor Field-of-View Checklist — пред-прогонная инвентаризация «что видит исполнитель»

> **Назначение:** обязательная инвентаризация ПЕРЕД любым контролируемым прогоном / стендом /
> A-B-плечом — всё, что попадает в поле зрения исполнителя, а не только репозиторий, который
> ты для него готовил. Парный к `patterns/blind-comparison-protocol.md` (тот — про судейство
> сравнения; этот — про чистоту стенда ДО прогона) и к `patterns/canary-write-probe.md`
> (исходящие записи стенда).
>
> **Провенанс:** M16 ERR-04 + ERR-05 (DEC-DEV-0235, пакет 7 волны носителей): плечо
> контролируемой пробы подхватило `~/.claude/CLAUDE.md`, 7 команд `/ecosystem:*` и глобальный
> кэш экосистемы; стенды несли всю будущую историю git, а протокол/приёмка лежали в соседнем
> видимом каталоге. «Обе ошибки — одна и та же: я готовил РЕПОЗИТОРИЙ, а надо было готовить
> ВСЁ, ЧТО ВИДИТ ИСПОЛНИТЕЛЬ. Оба раза спасла случайность, а не процедура.»
>
> **Когда запускать:** перед стартом ЛЮБОГО контролируемого прогона (A/B-проба, калибровка
> харнесса, изолированный стенд, «чистое» плечо) — до первого промпта исполнителю.
> **Правило:** каждый пункт даёт ФАКТ (вывод команды), а не ощущение «вроде чисто».

## Таблица инвентаризации (M16_ERROR_LEDGER, свод ERR-04/05/06)

| Что проверить | Команда | Что считается провалом |
|---|---|---|
| История и происхождение репозитория | `git log --all --oneline \| wc -l`, `git remote -v` | видна история дальше точки старта; есть remote на источник |
| Рабочий и родительский каталоги | `ls -a ~/work`, `ls -a <cwd>/..` | видны артефакты эксперимента, соседнее плечо, протокол |
| Пользовательский уровень Claude | `ls ~/.claude/{commands,skills,agents,hooks}`, `cat ~/.claude/CLAUDE.md` | доступны команды/кэш изучаемого инструмента |
| Область MCP | `claude mcp list` в каталоге каждого плеча | сервер одного плеча виден другому |
| Что ещё запущено на машине | `docker ps`, `ss -tlnp` | доступен работающий экземпляр эталонной реализации |
| Скрытые каталоги оператора | `ls -a ~ \| grep -i <тег эксперимента>` | приёмка/протокол лежат на видном месте |
| Исходящие зависимости самого стенда (ERR-06) | `tr '\0' '\n' < /proc/<pid>/environ`; грепом по коду — `API_BASE_URL`, `*_URL`, `*_ORIGIN`, значения по умолчанию | приложение по умолчанию ходит на чужой адрес |
| Куда реально ложится запись (ERR-06) | одна канареечная запись → проверить, что строка появилась **в целевой БД** (полный протокол — `patterns/canary-write-probe.md`) | запись ушла не туда, куда смотрит проверка |

## Процедура

1. Прогнать ВСЕ строки таблицы, зафиксировать вывод каждой (файл рядом с протоколом прогона).
2. Любой «провал» → устранить (чистый стенд: `git archive` + свежий `git init`, а не clone;
   изоляция `~/.claude` уровня плеча; протокол — вне видимых каталогов) и перепрогнать строку.
3. Только после 8/8 фактов «чисто» — первый промпт исполнителю.
4. Отчёт прогона обязан ссылаться на файл инвентаризации (иначе чистота стенда — мнение).

## Анти-паттерны

- **«Я же сам его готовил»** — изоляция проверяется там, где о ней подумали, и дырявит там,
  где не подумали (история git, remote, соседние каталоги, глобальный кэш). Список — вместо
  памяти.
- **Проверка после старта** — исполнитель уже мог прочитать утёкшее; инвентаризация после
  первого промпта не восстанавливает чистоту.
- **`git clone` для «чистого» стенда** — клон несёт всю будущую историю (ERR-05): плечо может
  посмотреть готовую реализацию через `git show`. Только `git archive` + `git init`.
