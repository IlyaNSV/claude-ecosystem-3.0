### Инварианты И ЗАПРЕТЫ (решены этой сессией — НЕ пересматривать без новых данных)

1. **Наблюдаемость строится НЕЗАВИСИМО от Кондуктора — он ПОТРЕБИТЕЛЬ каналов, не место
   их постройки.** Обоснование из его же канона: I-1 (субстрат READ-ONLY, «новых API не
   заводим») · плоскость 6 «UI не строим» · §Состав кладёт «операторские грабли VM» в
   скилл `vm-factory-ops`, а не в код пульта. НЕ блокировать этот трек на roadmap H0-H4.
2. **Два канала, не смешивать** (ратифицировано, `CONDUCTOR.md §Наблюдаемость`):
   - **машинный** — решения (sweep/Q&A/вердикты) ТОЛЬКО из событий/транскриптов (I-6/C3);
     скрести экран для решений запрещено. **Этот трек машинный канал НЕ трогает.**
   - **человеко-визуальный** — надзор владельца глазами + визуальные Q&A агента («как
     выглядит UI»). **Наш трек = ТОЛЬКО этот канал.** Он ДОПОЛНЯЕТ observability, не
     становится входом для авто-решений.
3. **Дома реализации по слоям (куда что коммитить):**
   - слои 1/2/4 (RDP/noVNC/ttyd/vm-shot) → скилл `vm-factory-ops §7` (вне репо) + конфиг VM;
   - слой 3 (headed+video/trace) → репо экосистемы (P8 UJA `orchestrator/`) + пилот
     (playwright config/journeys); DEC-DEV при стройке runtime (next-free — проверить
     `node dev/meta-improvement/scripts/next-dec-dev.js`, на 2026-07-28 был 0227);
   - слой 5 / десктоп-пульт → **НЕ этот трек** (UI-слой Кондуктора, ждёт его фаз).
4. **VM — ОБЩИЙ ресурс:** §0-проба занятости (`vm-factory-ops §0`) ПЕРЕД любым разрушающим
   (poweroff/reset/snapshot/modifyvm/`vrdemulticon on`/kill). Чужое не трогать (сейчас на
   VM — `radar-bot`). Гасить только СВОИ отслужившие.
5. **Порты биндить ТОЛЬКО на `127.0.0.1`** (наружу не торчит; VRDE `authtype=null` допустим
   ровно поэтому). Всё git/сеть/ssh с хоста — `dangerouslyDisableSandbox: true`.
6. **Записи/факты — материализовать** (эмпирика прогонов → `vm-factory-ops §7` как SSOT
   операторских грабель; статус трека → этот шов + память).
