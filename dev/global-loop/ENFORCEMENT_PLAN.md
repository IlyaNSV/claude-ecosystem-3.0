# ENFORCEMENT_PLAN — волна носителей принуждения (по итогам анализа эффективности)

status: **RATIFIED-BY-OWNER 2026-07-30** — «го» на **шаг 0 + пакеты 1–2**; пакеты 3–7 — по
новому «го» после контрольного среза (П-3). Rationale и решения — DEC-DEV-0230.
Провенанс: `analysis/REPORT.md` (§7 синтез) · `analysis/M16_RESULT.md` · DEC-DEV-0228/0229 ·
`ECOSYSTEM_FEEDBACK_RUN-B.md` (12 открытых системных пунктов из 13; B3 закрыт PR #4) ·
`analysis/M16_ERROR_LEDGER.md` (свод enforcement-кандидатов) · coverage-check AS IS
(recon 2026-07-30: 10 агентов + адверсариальная верификация 6 несущих утверждений).

**Цель одной фразой:** конвертировать уроки двух прогонов и анализа эффективности
**в гейты и обязательные разделы шаблонов, а не в документы** (вход следующей единицы
трека — SEAM.md §Очередь). Главный вывод анализа: работает то, у чего есть носитель
принуждения; всё, что держится на дисциплине, дрейфует за ~16 дней и срезается.

## Решения владельца (2026-07-30, зафиксированы)

1. **Объём «го»:** шаг 0 + пакеты 1–2. Контрольный срез датчиков после пакета 2 →
   новое «го» на продолжение.
2. **Режим новых носителей: сразу hard-block** (V-rule матрицы доступа, гейт констант,
   deviations-блок, линтер брифа). Это **архитектурное исключение** из дефолта экосистемы
   «warn, don't block» (DEC-DEV-0047 §4) — обоснование: рецидив P21 случился ПОСЛЕ
   ратификации I-8, warn-канал измеримо не меняет поведение (I8_FIDELITY: «ни один гейт
   не отказал ни разу»); фиксируется DEC-DEV-0230. Отвергнутая альтернатива —
   warn-first с эскалацией по рецидиву (рекомендация ассистента) — отклонена владельцем.
3. **Дом линтера брифа (пакет 3):** код в экосистеме (SSOT канонических путей),
   вызов из пульта — по прецеденту `orchestrator/lib/run-ledger.cjs` ← `factory.cjs`.
4. **PR результатов анализа в main** — заводить немедленно (шаг 0.1).

## Принципы исполнения (анти-разрастание)

- **П-1. Нулевая сумма текста.** Каждый пакет обязан заполнить колонку «что сворачивается»:
  правило, получившее носитель, схлопывается из прозы в указатель (pointer-collapse,
  прецеденты DEC-DEV-0197/0227). Метрика: число обязательных always-on строк канона
  после плана ≤ чем до. Пакет без этой колонки не готов к исполнению.
- **П-2. Детерминизм-предпочтение.** Носитель по умолчанию — скрипт/схема, не LLM-правило;
  LLM-суждение только там, где детерминированная проверка невозможна (обосновать в
  DEC-DEV пакета). Урок «механику — скриптам, не агентам».
- **П-3. Датчик-сторож + стоп-правило.** Исполнение попакетное; между пакетами снимаются
  доступные датчики: статические сразу (доля дефектов без гейта — пересчёт
  `analysis/DATASET/defects.csv`-класса; счётчик always-on строк), cost per resolved
  intent — на ближайшем живом прогоне. Рост цены без падения дефектов-без-гейта →
  пакет пересматривается, следующий не стартует.
