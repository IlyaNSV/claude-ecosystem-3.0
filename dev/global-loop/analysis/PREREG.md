## 0. Правила честности (применяются ко всем числам)

1. **Самоотчёт ≠ факт.** `ASSIST_LOG.md`, `SUMMARY-COND-*`, финальные сообщения сессий — **claims**. Факты: git-коммиты и диффы, состояние деплоя, транскрипты (**tool_use + tool_result**, а не нарратив), файловая система, UJA-трассы.
2. **Пометки:** `[UNVERIFIED-CLAIM]` — число/утверждение опирается на claim без детерминированной проверки; `[POST-HOC]` — формула добавлена/изменена после взгляда на данные; `[SKIPPED: причина]` — замер закрыт без подсчёта.
3. **Скрипт > судья.** Всё детерминированно проверяемое считается кодом. LLM-судья — только для суждений (качество спеки, соответствие интенции, профанация).
4. **Провенанс обязателен.** Каждая строка датасета несёт `source_file` (+ строка/коммит, где применимо). Вердикт без провенанса недействителен.
5. **Округление/представление:** доли — 3 знака; токены — целые; время — минуты (1 знак). Медиана указывается вместе с n и разбросом (p25–p75), среднее — только рядом с медианой.

## 3. Единицы измерения (общие определения)

- **Сессия** = один основной `*.jsonl` (`sessionId`). `--resume` продолжает тот же файл ⇒ файл может покрывать несколько календарных дней.
- **`wall_span`** = `last_ts − first_ts` по записям файла. **`wall_active`** = сумма межсобытийных интервалов **≤ 15 мин** (интервалы больше считаются простоем; порог объявлен до данных; известный API-stall 31 мин попадёт в простой и будет учтён отдельно как инцидент).
- **Токены** (из `message.usage`, суммарно по assistant-записям): `out` = `output_tokens`; `in_fresh` = `input_tokens`; `cache_read`; `cache_create`. **`ctx_processed`** = `in_fresh + cache_read + cache_create`. Основная единица сравнения объёма работы — **`out`**; `ctx_processed` — единица «прокачки контекста».
- **Денежная конвертация не входит в базовые формулы.** «Cost per resolved intent» первично считается в **токенах (out и ctx_processed) и wall-минутах**. $-приложение — опционально, с явной датой и источником прайса (внешний факт ⇒ Informed Fetch), и помечается как оценка.
- **Слой:** `host` (хост-сессии кондуктора, `cwd` = ecosystem/ce3-wt) · `executor` (сессии на VM в проекте пилота) · `subagent` (файлы под `subagents/`).
- **Эпоха:** `pre-conductor` = сессии пилота с началом < 2026-07-17T00:00Z (baseline M5) · `RUN-A` = 07-17…07-20 · `RUN-B` = 07-22…07-23.
- **Дефект** = дефект продукта/процесса, зафиксированный в реестре 3.3 с провенансом (симптом + место). **Интенция** = отдельная владельческая просьба/проблема/«го» (см. M1).
- **FM** = feature-модуль пилота (7 в RL-001).

## 5. Формулы и пороги интерпретации

> Пороги объявлены **до** подсчёта. Порог — не приговор, а заранее заданная граница «спокойно / внимание / тревога», чтобы толкование не подгонялось под результат.

### Фаза 0

| Метрика | Формула | Спокойно | Внимание | Тревога |
|---|---|---|---|---|
| **M7 claim-accuracy** | доля claim'ов с вердиктом `TRUE` среди верифицируемых, по типам (код-фикс / деплой / тест-PASS / док-синк); n ≥ 30, стратифицированно | ≥ 0.90 | 0.70–0.90 | < 0.70 |
| **M7 применение** | ≥0.90 → ledger пригоден как навигация и как данные; 0.70–0.90 → только навигация, числа из ledger не переносятся в отчёт без верификации; <0.70 → ledger дисквалифицируется как источник, все производные числа считаются заново | — | — | — |
| **M12 loop-ratio** | `dup_toolcalls / tool_calls_total`, где dup = повтор идентичного `arg_digest` в той же сессии (2-й и далее) | ≤ 0.10 | 0.10–0.20 | > 0.20 |
