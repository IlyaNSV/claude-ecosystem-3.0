# Рубрика — разрешение интенции владельца (M1)

> Зафиксирована **до** прогона судьи (PREREG §1, §9.4). Судья — Opus 5, фиксирован на весь анализ;
> judge ≠ author (оцениваемый материал породили Fable 5 и Opus 4.8).

## Что оценивается

Для каждой интенции владельца (дословный текст из хост-транскрипта) и приложенного пакета свидетельств
(сессии, коммиты с subject'ами, процессные прогоны с вердиктами, записи ledger в окне) вынести **один**
вердикт разрешения и указать провенанс.

## Шкала вердиктов

| Вердикт | Критерий (обязателен провенанс) |
|---|---|
| `RESOLVED_1` | Интенция закрыта в первом же окне: в окне есть работа (коммиты/процессы), которая по содержанию отвечает именно этой интенции, и есть подтверждающий машинный сигнал (зелёный процесс, деплой, тест-прогон) **или** явная фиксация результата в ledger с якорем |
| `RESOLVED_N` | Интенция закрыта, но потребовала ≥2 заходов: работа продолжилась за пределами окна / повторялась в последующих сессиях (виден догон, remediation, повторный прогон) |
| `REOPENED` | Интенция была объявлена закрытой, но та же тема возвращается в более поздней интенции владельца (в списке всех интенций есть повтор темы) |
| `NOT_RESOLVED` | В окне и позже нет работы, отвечающей интенции, либо работа явно не достигла цели |
| `NO_WORK_EXPECTED` | Интенция не требовала работы над кодом/продуктом: организационная реплика, уточнение статуса, решение об отказе от действия, распоряжение об остановке |
| `UNCLEAR` | Пакета свидетельств не хватает для вердикта (обязательно указать, чего именно не хватает) |

## Правила судейства

1. **Только по свидетельствам из пакета.** Ни одного вердикта «по смыслу» без цитаты, sha или id процесса. Вердикт без провенанса недействителен.
2. **Совпадение по содержанию, а не по времени.** Коммиты, попавшие в окно, но относящиеся к другой теме, — не свидетельство разрешения. Прямо отмечай такие случаи (`работа в окне есть, но не по теме`).
3. **Машинный сигнал сильнее нарратива.** Запись ledger «сделано» без якоря — не подтверждение; вердикт процесса из run-ledger, sha коммита, релиз — подтверждение.
4. **Не додумывай намерение.** Если формулировка владельца допускает два прочтения, вердикт `UNCLEAR` с указанием развилки лучше, чем угадывание.
5. **Тип интенции важен.** «Проверь, как дела» и «останови всё» — это `NO_WORK_EXPECTED`, а не `NOT_RESOLVED`: отсутствие коммитов здесь ожидаемо и не является провалом моста.
6. **Сомнение — в сторону меньшего успеха.** Если между `RESOLVED_1` и `RESOLVED_N` неясно — ставь `RESOLVED_N`; между `RESOLVED_N` и `NOT_RESOLVED` — `NOT_RESOLVED` с пояснением.

## Формат ответа судьи (строго)

Для каждой интенции — одна строка JSON:

```json
{"intent_id":"I001","verdict":"RESOLVED_1","evidence":"<sha/процесс/цитата — чем подтверждено>","note":"<1 фраза: что именно было сделано или чего не хватило>","topic":"<3-5 слов: тема интенции, для детекта переоткрытий>"}
```

Никакого текста вокруг JSON-строк. Одна строка = одна интенция, порядок сохраняется.

## Калибровка

Перед массовым прогоном судья получает 5 голден-случаев с известным ответом (проверены скриптово).
Цель согласия — ≥80%. Расхождение на голден-наборе фиксируется в отчёте вместе с итоговыми числами.
