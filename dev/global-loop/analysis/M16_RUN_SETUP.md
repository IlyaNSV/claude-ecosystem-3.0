## 5. Задание плечам

**Тело — побайтно одинаковое у A и B:**

```
В репозитории есть продуктовая спецификация в `.product/`. Построй работающий MVP функциональных
модулей FM-001 и FM-002: приложение должно запускаться, ключевые пользовательские сценарии из
спецификации должны проходить end-to-end. Тесты, схема БД, миграции — на твоё усмотрение. Когда
считаешь работу законченной — сообщи и остановись.

Условия окружения:
- PostgreSQL 16 и Redis 7 уже запущены; строки подключения — в `.env` в корне репозитория.
- Учётных данных внешних сервисов (распознавание речи, перевод, синтез речи, отправка почты,
  платежи, CAPTCHA) нет и получить их нельзя.
- Внешние коннекторы аккаунта (почта, календарь, диск) использовать нельзя.
- Для веб-приложения свободны порты 4100 и 4101.
- Интернет доступен.
```

**Единственная различающаяся фраза** (пререга §4 разрешает ровно одну — про доступный
инструментарий), выровненная по форме: назвать фреймворк, префикс его команд, где обзор.

- **A:** `Инструментарий — установленная в репозитории экосистема процессов (команды /product:, /design:, /integrator:, /ecosystem:; обзор — CLAUDE.md в корне).`
- **B:** `Инструментарий — установленный фреймворк GSD Core (команды /gsd-…; обзор — /gsd-help) и подключённые MCP-серверы: playwright, chrome-devtools, context7, filesystem, sequential-thinking, memory, prisma.`

**Блок «Условия окружения» — добавление к пре-регистрированному тексту**, отсутствовавшее в
пререге §4. Причина: без него плечи проиграли бы не отсутствию канона, а незнанию среды (пререга §2
прямо требует «чтобы плечо B не проигрывало из-за незнания окружения»). Блок **идентичен** у обоих и
не подсказывает способ работы. Запрет на внешние коннекторы аккаунта добавлен, чтобы исключить
реальные внешние сайд-эффекты (коннекторы claude.ai — Gmail, Календарь, Диск — доступны на VM на
уровне аккаунта и одинаковы для обоих плеч).

## 6. Условия прогона

- Сессии: `tmux` `cc-m16a` / `cc-m16b`, запуск `DISABLE_AUTOUPDATER=1
  CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false claude --dangerously-skip-permissions`, модель пинуется
  явно и одинаково для обоих.
- Плечи идут **последовательно**; инфраструктура каждого поднимается заново из одинакового
  состояния. Эффект «прогретого окружения» у второго плеча неустраним при n=1 — объявлен
  ограничением (пререга §12), а не скрыт.
- Вмешательство: только технические разблокировки, одинаковые для обоих, каждая пишется в протокол.
  Владельческий класс (деньги, прод, реальные секреты) — эскалация, ответ даётся обоим одинаково.
- Завершение объявляет сама сессия. Harvest: основной транскрипт **и** `subagents/**` (иначе
  теряется 27–67% расхода). Токены считаются по `message.usage.output_tokens`, не по `totalTokens`.
